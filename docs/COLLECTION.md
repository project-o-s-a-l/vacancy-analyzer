# Источники вакансий

Планировщик передаёт запрос адаптеру источника. Адаптер отдаёт нормализованные модели `Vacancy`. Каталог сохраняет их, отслеживает изменения и объединяет дубликаты. Ранжирование работает с сохранёнными моделями.

## Подключение адаптера

Установите пакет нужного источника в то же окружение, где запускаете приложение. Для контейнера пакет устанавливают в образ приложения. Отдельный пакет регистрирует объект адаптера через стандартную точку входа Python.

```toml
[project.entry-points."vacancy_analyzer.sources"]
html = "my_source.adapter:adapter"
```

Имя точки входа соответствует режиму сбора. Для HeadHunter предусмотрены `html` и `api`, для остальных интеграций — `habr_career`, `trudvsem`, `superjob` и `avito`. Метод `adapter.open(settings)` возвращает асинхронный контекстный менеджер. На входе в контекст он предоставляет источник с [интерфейсом VacancySource](../src/collectors/base.py), на выходе освобождает ресурсы.

```sh
vacancy-analyzer collect --source trudvsem --pages 1
vacancy-analyzer catalog-status
```

Для регулярного сбора предусмотрена команда `vacancy-analyzer collect --watch`. Список площадок и интервалы задаются в [примере конфигурации](../.env.example). Подключение к хранилищу описано в [руководстве по запуску](../README.md).

## Сохранённые страницы

Импорт страниц и подготовка выборки из сохранённых ответов требуют соответствующего адаптера. Каталоги `data/` и `artifacts/` предназначены для локальных данных. Для проверки работы приложения на учебных примерах используйте `evaluation-prepare` и `evaluation-validate`.
